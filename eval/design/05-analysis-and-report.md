# 05 · 指标分析与标准化评测报告

> 状态：方案稿（待评审）· 对应 Plan revision 2 · 2026-10-08

## 1. 指标分析方法

### 1.1 阈值判定（用户硬口径，不得放宽）

| 维度 | 判定指标 | 阈值 | 判定规则 |
|---|---|---|---|
| D1 | 首次成功率（pass@1） | ≥ 80% | 通过=达标；同时报告 95% Wilson CI |
| D1 | 3 次重试内成功率 | = 100% | 一例失败即不达标 |
| D2 | judge 四维均分 | ≥ 3.5 | 代码/文档产物分别计算 |
| D2 | judge 最低维度分 | ≥ 2.0 | 任一维度 <2.0 即不达标 |
| D2 | 验收命令通过率 | ≥ 90% | 按 cmd 项聚合 |
| D3 | 节点评分 vs 基线 | 不下降 | 与首轮基线比较（Δ≥0） |
| D4 | 修复后评分 / 无缺陷评分 | ≥ 80% | 逐相邻对比对 |
| D5 | 人工评分 ≥4.0 占比 | ≥ 80% | 抽样 6 例中 ≥4.8 例（按比例口径，样本小仅作方向性） |
| D-Config | 拓扑违例 / 禁用节点调用 | = 0 | 一次违例即不达标 |
| D-HITL | 分流准确率 | = 100% | 20 条全对 |

### 1.2 聚合与呈现规则（全部量化）

- **分层统计**：通过率、评分按难度层（simple/medium/complex）分别统计，附总体。
- **分布**：judge 总分给出均值 ± 标准差与分段计数（≤2 / 2–3 / 3–4 / ≥4）。
- **区间**：比率类指标一律附 95% Wilson CI；样本量导致的低分辨率在报告中显式声明（30 例对 80% 阈值的 CI 半宽约 ±14 个百分点）。
- **量化纪律**：每个结论句必须带数字；禁止「表现良好」等无数字表述；时间/token 仅记录不判定（deferred）。

### 1.3 归因分析

- 失败归因：错误类型 × 失败任务交叉表；对每个失败 case 给一句根因假设（引用采集证据）。
- 校准健康度：judge-人工偏差（6 例抽样）均值与最大偏差；命中告警须记录处置。
- 跨轮趋势：同 tag 同用例集的历史轮对比（Δ 与方向），仅描述不外推。

## 2. 标准化评测报告模板（每轮一份，发布介绍用途）

> 模板骨架；`<>` 为填空。结构对齐行业通用评测报告逻辑：对象 → 方法 → 结果 → 分析 → 结论 → 可复现（行业无单一标准，此结构为多来源共识的收敛，参考 [InfoQ agent 测试与评测报告实践](https://www.infoq.com/ai-agent-testing-evaluation)、[FutureAGI 多模型评测指南](https://futureagi.com/Blog)）。

```markdown
# Ddo-Code-Flow 有效性评测报告

## 0. 元信息
- 被测版本（tag）：<vX.Y> ｜ 用例集版本：<CSn.n.n> ｜ 评测日期：<YYYY-MM-DD>
- 被测配置：宿主 <name+version> ｜ 模型 <model> ｜ 工作流 <basic/standard>
- 结论一句话：<X/7 维度达标；最弱项为 <维度+数字>>

## 1. 概要（一页结论）
| 维度 | 关键指标 | 数值 | 阈值 | 判定 |
|---|---|---|---|---|
| <D1> | <首次成功率> | <85%（CI 68–94%）> | ≥80% | ✅ |

## 2. 评测对象与方法
- 被测对象与映射（引 01 分册映射表结论）；用例集构成（分层计数表）；judge 配置（模型、rubric 版本、校准状态）；自动化流程版本（03 分册策略器口径）。

## 3. 结果
- 3.1 端到端：pass@1 / 重试型 pass@3、失败分布表（任务 × 错误类型）
- 3.2 产物质量：分维度评分表（代码/文档分开）、验收通过率
- 3.3 节点级：D3 各任务评分 vs 基线；D4 各相邻对比对
- 3.4 配置与人机：D-Config 违例明细；D-HITL 20 条分流结果与误判类型

## 4. 分析
- 达标/未达标归因（引用失败 case 根因假设）；分层差异（哪层拖累）；judge-人工偏差与校准处置；本次口径声明（重试型 pass@3 语义、CI 分辨率）。

## 5. 结论与建议
- 有效性命题判定：<成立/不成立/部分成立>（引用 §1 表）；下一步量化建议（最多 3 条，每条带数字目标）。

## 6. 可复现附录
- 精确命令序列（tag 检出 → runner 调用 → 参数）；用例集 hash；沙箱与原始数据位置（仓库外路径）；单价表与抓取日期；已知的运行环境差异。
```

**保留策略（用户约束）**：项目内仅保留**最新一份**报告（建议落 `eval/reports/REPORT.md`，实现轮次确定）；旧报告靠 git 历史追溯，不堆叠多份。原始采集数据不入库（06 分册）。
