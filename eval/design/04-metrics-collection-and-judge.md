# 04 · 指标获取与 Judge 设计

> 状态：方案稿（待评审）· 对应 Plan revision 2 · 2026-10-08

## 1. 指标获取

### 1.1 确定性指标通道（脚本可直接计算）

采集点清单见 03 分册 §6；本节定义由原始采集到指标的换算：

| 指标 | 换算来源 | 公式/规则 |
|---|---|---|
| 首次成功率（pass@1） | 各 case 的 run 终态与失败标记 | 首跑即完成且验收通过的 case 数 ÷ 有效 case 数 × 100% |
| 3 次重试内成功率（重试型 pass@3） | 重试日志 | 最终完成且验收通过的 case 数 ÷ 有效 case 数 × 100% |
| 失败节点分布 / 错误类型 | rollback 与错误类型枚举记录 | 按失败发生任务名 × 错误类型计数 |
| 单元测试通过率 | 验收命令输出 | 通过 cmd 项 ÷ 全部 cmd 项 × 100%（按 case 聚合再平均） |
| 门分流准确率 | 门交互日志 vs 预期跳转 | 一致条数 ÷ 20 × 100% |
| 拓扑合规 | .state.json 快照时间线 vs 预设 DAG | 违例次数（应为 0） |
| 节点质量评分（D3/D4） | judge 输出 | 见 §2 |
| 时长 / token / 成本 | 时间戳 / §1.2 | 仅记录，判定留给 deferred 维度 |

### 1.2 token 与成本通道（行业适配：转化）

行业做法是 harness 内嵌计量（如 SWE-bench 系按 per-call token usage 计费）。ddo 的执行在宿主代理内，CLI 不经手 token，**外置采集**为必选转化：

- **主通道（推荐）**：宿主会话转录中的 usage 记录（如 Claude Code 会话转录的逐消息 token usage 字段）。实现轮次须先核验字段可得性并固化解析器；解析失败时该 case 的成本指标记缺失，不得估算填充。
- **对账通道**：供应商用量面板按轮对账（误差带 ±5%），仅用于校核主通道，不进指标。
- 成本换算采用报告元信息中固化的单价表（记录抓取日期），跨轮比较须用同一单价表。

## 2. Judge 设计（LLM-as-judge）

### 2.1 设计基线（行业共识，转化采用）

方法遵循 MT-Bench 系共识（[Zheng et al., NeurIPS 2023](https://papers.nips.cc/paper_files/paper/2023/hash/91f18a1287b39be3523d0394e651e7c2-Abstract-Conference.html)；[Galileo 实践](https://galileo.ai/blog/llm-as-a-judge)；[Comet 指南](https://www.comet.com/site/blog/llm-as-a-judge/)）：rubric 进 prompt、盲评去标识、位置偏差用换序消偏、judge 与人工一致率 ~80% 为可用线、人工校准常态化。

**关键转化**：行业多用于成对比较（pairwise），绝对评分更难且更偏——ddo 是**单产物场景**（无天然对照组），故以「rubric 绝对评分 + 高频人工校准」为主；成对比较仅在后续优越性命题（deferred）引入，届时用换序平均消偏。

### 2.2 judge 模型选型（待讨论项 ①，选项对比 + 推荐建议）

| 选项 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A · 同族不同代际 | 与被测模型同厂商、更新或更稳定代际 | 领域理解一致 | 自我偏见风险（同族偏好），违背隔离意图 |
| B · 异族旗舰 | 不同厂商的旗舰模型 | 满足 judge≠被测隔离；评分质量高 | 成本较高 |
| C · 本地/轻量模型 | 本地部署或小参数模型 | 成本低、无外部依赖 | 评分能力不足，校准难达标 |

**推荐：B（异族旗舰）**，并满足 judge 模型族 ≠ 被测模型族（校准四件套之隔离项）。此为**建议**，最终选型待用户讨论确认（含具体型号与单价表）。

### 2.3 judge prompt 框架（待讨论项 ②，推荐设计）

```
角色：你是严格的软件产物评审员。
输入：case 需求原文 + acceptance 清单 + 被评产物（已去标识，不告知来源与模型）。
评分对象：按 rubric 维度逐一打 1–5 分（整数）：
  完整性（acceptance 覆盖）/ 正确性（逻辑与事实错误数）/ 可维护性（结构与可读性）/ 一致性（与需求术语和约束一致）
输出：严格 JSON：{case_id, 维度分:{...}, 总分(加权均值), 理由:{每维度≤3句, 引用产物原文锚点}, 置信: high|low}
约束：先逐条核对 acceptance，再评质量；发现事实错误直接在正确性扣分并引用；不比较想象中的其他产物。
```

要点：输出强制 JSON（可脚本入库）、理由须带产物原文锚点（可抽查防幻觉）、置信低分触发人工复核。rubric 锚点样例（1/3/5 分行为描述）在用例集定稿时按维度补齐。

### 2.4 其余三个评分标准待讨论项（选项对比 + 推荐建议）

| 待讨论项 | 选项 | 推荐（建议） |
|---|---|---|
| ③ 结构性指标 | A：行数、注释率等表面积指标；B：格式合规 + 必要章节/产物存在性（脚本判定） | **B 为主**：B 判定确定且难 gaming；A 仅作辅助观测不作判定（行数类指标易被仿造） |
| ④ 端到端指标 | A：仅单元测试通过率；B：测试 + 构建 + 运行冒烟组合 | **B 组合**：按用例性质选配（纯文档类用例降为「格式校验命令」），权重在用例 acceptance 中声明 |

### 2.5 校准机制四件套（用户定义的落地设计）

| 机制 | 落地设计 | 量化口径 |
|---|---|---|
| 对照样本 | 人工预评 5 个锚点产物（覆盖 1–5 分段），每 50 次 judge 调用混入 1 批 | judge 分与人工分差 >0.5 即命中告警 |
| 偏离告警 | 命中即暂停该 judge 全部未出分任务，人工复核后决定续用或更换 | 告警状态与处置记入报告 §4 |
| Judge 模型隔离 | judge 模型族 ≠ 被测模型族；配置写入报告元信息 | 违例=当轮 judge 分数全部作废 |
| 盲评 | 产物去标识（剥离作者/模型/时间线索）；多产物场景随机序呈现 | 每轮抽检去标识完整性 |

人工抽检与 D5 共用通道：每轮从 30 例中随机抽 **6 例（20%）**人工评分，同时承担 judge 校准点与 D5 判定样本（D5 判定阈值见 05 分册）。
