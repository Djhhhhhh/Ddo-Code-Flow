# prompt-rules.md — 出题层修正规则库

> 需求 §6：Prompt 修正双层规则。**出题层修正（评测前，冻结）**由本规则库约束；**工作流层修正（评测中）是被测能力**，由模型 + 工作流自己做，评测方不得替做。

## 1. 判定标准（哪一层修）

| 判定 | 归属 | 处理 |
|---|---|---|
| 不补则题目无解/无法验收（接口名、字段名、环境约束缺失） | 出题层 | 写死进 prompt.final.md，记入 prompt.diff |
| 属于需求本身的模糊点（策略、次数、优先级、风格取舍） | 工作流层 | 留给被测模型；同时登记进 clarify.json 可澄清项清单 |

## 2. 允许的修正类型（出题层）

1. **补可解性**：补接口名/字段名/数据格式等使题目可解可验收的最小信息；
2. **消歧义**：消除与验收标准冲突的表述歧义（仅限「不补则验收无法判定」者）；
3. **统一术语**：同一概念在题面内命名不一致时统一（保留用户原始术语并给映射）；
4. **补环境约束**：运行环境、版本锁定、网络可达性等执行前提。

## 3. 禁止（硬约束）

- **禁止补需求决策**：次数、策略、优先级、默认值取舍等属于需求本身的决策，一律不得在出题层补入。
- 禁止把隐藏验收的判定阈值泄漏进题面（题面只给可验收描述，如「不挤在一圈」）。
- 禁止修改 `prompt.raw.md`（用户原始 prompt 冻结；修正只产生 final）。

## 4. prompt.diff 固定模板

每道题包的 `prompt.diff` 按以下段落实体记录（无修正时显式记「空 diff」）：

```
# prompt.diff — <题名>

## D-1
- 位置：<prompt.raw.md 中的段落/行锚点>
- 类型：补可解性 | 消歧义 | 统一术语 | 补环境约束
- 修改前：<原文片段>
- 修改后：<修正片段>
- 理由：<为何不补则无解/无法验收>

复核人：________  日期：________
```

## 5. 流程与复核

1. 新增/修订题：由固定修正模型（**第三方 judge，与被测模型不得同源**）按本规则库生成 `prompt.diff`；
2. 人工复核：**新增题每轮复核，核心集一次性复核**（复核人签署于 diff 文件）；
3. 冻结四件套：`prompt.raw.md` / `prompt.final.md` / `clarify.json` / `acceptance/` 复核后冻结，评测期不得改动；
4. 披露：`prompt.diff` 入库随题包版本控，对外宣传被质疑时可出示。

## 6. 首批核心集记录

三道核心题（`q_threejs-orbit-scene` / `q_export-command` / `q_regression-trap`）均为**空 diff**（原文即可解可验），作为规则库的首批样例；其需求本身的模糊点（球面均匀的实现、组合行为、缺省路径惯例等）全部留在工作流层，登记于各自 `clarify.json`。
