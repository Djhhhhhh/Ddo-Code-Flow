### 2.2 任务输入（固定示例，保证跨轮可比——与 v2-beta 一致）

> 开发个本地 ddo-code-flow 工作流可视化工具：语言用 node，通过从用户根目录的索引文件检查到本机执行过程中的 .state.json 来可视化执行流程，html 渲染的图都用 svg 来画，线不要出现相交的情况。

换任务须满足：单文件交付物 / 可写 cmd: 验收条目 / 天然含 1–2 个 BQ。F18 专项改用可丢弃的测试仓库内小改动任务。

### 2.3 决议脚本（P0 主链门交互既定序列）

## 3. 执行步骤（含断言）

> `$SP` = statePath；`$SB` = 沙箱绝对路径；`$DH` = 该轮 DDO_HOME；CLI 一律 `node tools/cli.js …`。

### P0 主链（每轮必做）

| 步 | 动作 | 断言 |
|---|---|---|
| 0 | `node --test tools/tests/*.test.js` | 119/119 全绿，否则终止 |
| 1 | `list workflows` / `list tasks` | exit 0；workflows 含 basic/standard/pr-delivery/pr-delivery-issue；tasks = 20 且含 desc |
| 2 | `guide`（**F13**） | 四问齐全（goal freeText / mode 含「自定义」/ type / home 含「临时」）；连跑两次输出一致；无任何文件副作用 |
| 3 | `run start --project $SB --workflow standard --title <任务输入>` | F6：startedAt 本地时区且日期=runId 前 8 位；dirs 三绝对路径；currentStage=`requirement:01` |
| 4–5 | requirement → spec:01 → spec:02 门，按 §2.3 决议脚本 ①–⑧ | 每次拦截 exit 1 且 stderr 含后续操作指引；`gate present` 后 state 有 `presentedAt`；`gate interact` 后有 `interactions[]` 留痕；BQ 写回后 spec 含「对齐变化摘要」；驳回触发 `_del/rollback-1/`（F8） |
| 6–9 | plan / test-plan / tasking / coding，同 v2-beta 步 6–10 | F3/F4/F5 断言不变（tasking 就绪前抢跑 `exec --task coding` → exit 1） |
| 10 | verification：cmd 全 PASS + human 经宿主提问工具 | verification.log `ALL PASSED` 收尾 |
| 11–12 | review / reporting / reflection 门「同意」 | completed:true |
| 13 | `run finish --status done`（**F9/F14**） | `$DH/history/<runId>.zip` 存在；`unzip -t` 通过；zip 条目含 `.state.json` 与全部产物；jsonl 行 statePath 绝对；index 无残留；**项目内原 runDir 保留** |
| 14 | resume 复验（步 10 前插一次更佳） | 清单含位置概要；`resume --run-id` 双清单与 `gate present` 同源 |

### P0 专项 A：交互闭环对抗（独立小沙箱，basic 链）

| 步 | 动作 | 断言 |
|---|---|---|
| A1 | 开 spec 门后，跳过呈现直接 `next --decision 同意` | exit 1；stdout `blocked:"gate-unpresented"`；stderr 提示先 `gate present` |
| A2 | `gate present` → `gate interact --option 提问 --note "x"` → 再直接决议 | exit 1 `gate-unpresented`（交互使呈现过期） |
| A3 | 重新 `gate present` → 决议 | exit 0；closedGates 留痕 |
| A4 | `gate interact --option 不存在的选项` | exit 1，错误信息列出合法 in-phase 选项 |
| A5 | 转移型载体对称性：spec 门未呈现时 `rollback --stage spec`（作驳回用途） | exit 1 `blocked:"gate-unpresented"`；非门用途回滚不受限 |

### P0 专项 B：finish 演进 + 三级取值快验（三个一次性小沙箱）

| 步 | 动作 | 断言 |
|---|---|---|
| B1 | 正常 run 走完 → `run finish --status done` | F14（同主链步 13，双保险） |
| B2 | 新 run → `run finish --status aborted --no-archive` | **F15**：`$DH/history/` 无新 zip；runs.jsonl 无新行；index 移除 |
| B3 | `run start --ephemeral …` → 走两相位 → `run finish --status done` | **F16**：运行中 `$DH/tmp/<type>/<runId>/` 存在且项目 `.ddo/runs` 零创建；finish 后 tmp 目录删除、空 `<type>` 父目录修剪至 tmp 根 |
| B4 | `run start --tasks-dir <副本（prompt.md 加标记）>` → 无参 `exec --task requirement` | **F19**：输出含副本标记、不含仓库缺省任务文案；`validate`/`status` 同源读副本 |

### P1 专项 C：WTT worktree（可延期，见 §5）

| 步 | 动作 | 断言 |
|---|---|---|
| C1 | 冷启动问场景选 single → 从 title 提取分支名 → `git branch` + `git worktree add` | 分支 kebab-case ≤50 字符；worktree 目录存在 |
| C2 | `run start --project <worktree 绝对路径>` | **F17**：`state.git.branch` = 分支名、`worktreePath` = worktree 路径（自动注册，零新参数）；runDir ⊂ worktree |
| C3 | 走 basic 链至 finish → cleanup-worktree 收尾 | 未合并分支不删；离开 worktree 后 `git worktree remove` 成功 |

### P1 专项 D：PR 交付链（可延期；需专用测试仓库）

| 步 | 动作 | 断言 |
|---|---|---|
| D1 | 测试仓库内小改动 run → `pr-delivery` 预设启动 | 阶段链 deliver-pr → closeout-worktree |
| D2 | deliver-pr：推送 + 正式 PR + 合并确认门 | 门呈现走 `gate present` 统一入口；合并后 PR closed/merged |
| D3 | closeout-worktree：产物入库 + 免归档收口 + 清 worktree | **F18**：history 无该 run 归档（流程型）；分支按声明保留 |
| D4 | issue 变体：`pr-delivery-issue` + link-issue | PR 与 issue 双向评论关联存在 |

## 4. 比较基准（产物与留痕的期望形态）

| 对象 | 期望 |
|---|---|
| run 目录文件 | 同 v2-beta §4 全集；（驳回注入时）`_del/rollback-1/spec.md` 存在且原位消失 |
| state 留痕 | 4 门 gate 含 `decision`+`closedAt`；`presentedAt` 早于最后一条 interaction 的门必须已重新呈现；时间戳本地时区 |
| history | `runs.jsonl` 行 statePath 绝对；**`history/<runId>.zip` 与 jsonl 并存**（ephemeral/no-archive run 两者皆无） |
| agent 行为 | 每相位动手前有当次 exec 记录（F5）；门呈现一律经 `gate present`，无自造选项（F11 纪律面） |

## 5. 判定与记录

- **通过**：P0（主链 + 专项 A/B）全部断言成立 + §4 形态一致 → 定稿入 `eval/showcases/<版本>/`。
- **P1 延期规则**：无条件或成本不允许时，专项 C/D 可延期并在结论报告标注「P1 未覆盖 + 计划补齐时点」——**里程碑评审（如对外发布）前必须补齐**，平时延期不构成不通过。
- **不通过**：任一 P0 断言失败 → 按全局递增编号记 D-N（v2-beta 已用至 D-4，**本纪元从 D-5 起**），先记录后决策。
- **结论报告必备基础信息**：同 v2-beta §5 表（执行主体含模型名 / 被测版本与 commit / Node / OS / DDO_HOME / 执行窗口 / 测试基线 119）——缺项视为报告不合格。
