# ddo-code-flow 工作流可视化工具 Spec

> 本文档用于确认 agent 是否正确理解用户关于「本地 ddo-code-flow 工作流可视化工具」的需求。（revision 2：BQ-1/BQ-2 已回答写回）

---

## 对齐摘要

- 用户目标：在本地以图形方式查看 ddo-code-flow 工作流的执行流程。
- 期望交付：一个用 Node 编写的本地可视化工具，产出静态 HTML 文件（SVG 绘图）。
- 数据来源：用户根目录的索引文件 + 索引指向的运行中 run 的 `.state.json`。
- 关键边界：执行流程图中连线不得出现相交；历史 run 不在本次范围。
- 当前状态：BQ-1/BQ-2 已由用户回答并写回，本 spec 待批准。

---

## 用户目标

- 用 node 实现一个本地 ddo-code-flow 工作流可视化工具。
- 通过用户根目录的索引文件发现本机执行过程中的 `.state.json`，据此可视化执行流程。
- HTML 渲染的图用 SVG 画，线不要出现相交的情况。

---

## 范围与非目标

### In Scope

- 读取用户根目录的索引文件，发现本机运行中的 ddo-code-flow run。
- 读取运行中 run 的 `.state.json`，提取执行流程信息（阶段、当前位置、确认门状态）。
- 生成静态 HTML 文件，执行流程图以 SVG 绘制，浏览器打开即可查看。
- 保证流程图节点间连线无相交。

### Non-goals

- 用户未要求修改或增强 ddo-code-flow 本身，工具只读不改流水线状态。
- 用户未要求持续监听/自动刷新，本次不做常驻进程。
- 已结束的历史 run 可视化不在本次范围（BQ-1：仅运行中 run）。
- 本地 HTTP 服务与交互式刷新不在本次范围（BQ-2：静态 HTML）。

## 约束与保留术语

- 实现语言用 node（用户明确约束）。
- 保留用户术语：`.state.json`（ddo-code-flow 运行状态文件）、`索引文件`（用户根目录下的 ddo 全局索引，即 `~/.ddo/index.json`）。
