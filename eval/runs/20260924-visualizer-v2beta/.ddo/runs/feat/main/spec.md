# ddo-code-flow 工作流可视化工具 Spec

> 本文档用于确认 agent 是否正确理解用户关于「本地 ddo-code-flow 工作流可视化工具」的需求。

---

## 对齐摘要

- 用户目标：把本机 ddo-code-flow 的执行过程变成可视化的流程图。
- 期望交付：一个 Node 实现的本地工具，从用户根目录索引发现**运行中** run 的 `.state.json`，生成**静态 HTML 文件**，图为 SVG 绘制且连线不相交。
- 关键边界：本机、仅运行中 run、只读可视化；布局算法与依赖选型留给 Planning。
- 当前状态：BQ-1 / BQ-2 已由用户回答并写回，待用户批准。

---

## 用户目标

- 通过可视化查看 ddo-code-flow 工作流的执行流程——用户判断「现在各种产物和索引都规范化好了」，具备做成可视化条件。

---

## 范围与非目标

### In Scope

- 从用户根目录的索引文件（`~/.ddo/index.json`）发现本机**运行中** run 的 `.state.json` 位置。
- 解析 state 并以**静态 HTML 文件** + SVG 流程图呈现执行流程。
- 流程图连线不相交。

### Non-goals

- 不做已结束 run 的复盘可视化（`~/.ddo/history/` 与 `runs.jsonl` 不在数据源内）——BQ-1 定版。
- 不做多机 / 远程聚合——仅本机 `~/.ddo` 视野。
- 不提供对 run 的任何操作能力（推进、决议、回滚）——纯只读可视化。

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
