## 3. 问题信号归纳

- **S-1 run 生命周期与真实交付节奏错位**（证据：f494、e018、全量统计中 2 个 >3 天未收口 run）。跨 PR 评审周期的工作以「挂起数天」的 run 承载；e018 的实际收口动作发生在协议之外（closure.md + 从 coding:01 直接 finish）；startupCheck 已能发现 stale run 但无可操作的处置路径。
- **S-2 验证口径分裂**（证据：b4f3、d2be、e1ec、ea96）。basic 链无 verification 阶段 → 报告一律记「验证未执行」，但实际验证大量发生（coding 自检循环、联调实测表、20+ 日志文件），证据形态由各 agent 自由发挥（日志堆 / 内联表 / 清单），不可横向比较。
- **S-3 文档型 run 缺产出契约**（证据：b4f3）。coding validate 对「未声明产出」的任务返回 `validated: null` 空通过；本次 docs 类型 run 也无内建链路可依赖（当前 run 的 coding 产物是报告文档，靠 Plan 显式声明补位）。
- **S-4 split 阈值与大型 run 的冲突**（证据：b4f3 超限获批、ea96 11,999 贴线、d2be/d1c1/e1ec 被迫 split）。12,000 阈值在复杂 run 上要么逼出分册、要么造成「校验失败但用户批准」的非规范路径。
- **S-5 aborted run 零材料**（证据：1c9d、ccde、235a）。放弃原因、走到哪一步、为何重启，全部不可追溯；同目标重启的「试错对」在数据里只能靠标题相似性猜。
- **S-6 gate 上下文重组靠 agent 自救**（证据：b4f3 `coding-confirmation-prompt.md`、e018 `coding-prompt.md`/`plan-confirmation-prompt.md`）。确认门仅返回选项 payload，产物摘要要 agent 自己落盘重组——这是协议缺口而非个例（两个不同项目的 run 都这么做了）。
- **S-7 历史数据不可查询**（本次评估过程本身）。解析 30 条记录、解包 9 个 zip、核对重复项全部靠手搓 `node -e`/`unzip`；无 `history list/stats` 类命令，评估无法低成本周期化。
- **S-8 归档一致性缺陷**（全量统计 + 0560）。10 个空目录残留（zip 归档功能上线前的 `archiveState` 时代产物，内容已不在）；无任何一致性自检手段。
- **S-9 history.append 无幂等保护**（证据：d1c1 双记录）。同一 run 二次 finish 产生两条 done 记录、时长口径互相矛盾。
- **S-10 多仓库支持晚于真实需求**（证据：d2be/d1c1/ea96 手工双仓 → 85b2 才落地功能）。功能由外部使用倒逼产出是健康的，但期间 3 个 run 各自手工管理双 worktree、无统一留痕。
- **S-11 无 worktree 模式的工作区卫生**（证据：e1ec）。直跑项目目录时混入历史遗留改动，run 边界靠报告声明而非机制保证。

## 6. 具体改进建议条目（任务/协议级别，不排期）

**P0**

- **I-1 run 挂起/陈旧处置**：resume 清单为每个 run 附 `lastActiveAt` 与陈旧标记；提供挂起语义（或至少一键 `finish --status suspended`），把 startupCheck 的 stale 检测变成可操作动作。（对应 S-1）
- **I-2 正式化「旁路收口」**：把 e018 式收口变成 CLI 能力——`run finish` 支持 `--reason` 与自动生成的 closure 产物（含未提交材料清单、跳过的阶段、外部事件如 PR 链接），替代 agent 手写 closure.md。（对应 S-1）
- **I-3 aborted run 最小材料留存**：finish --status aborted 时保留 state 快照与一行放弃原因（用户可选填），空目录问题随之消失。（对应 S-5）
- **I-4 history.append 幂等**：按 runId 去重（同 runId 二次 finish 覆盖而非追加），并清理现存 d1c1 重复记录。（对应 S-9）
- **I-5 coding 验证小结结构化**：coding 自检循环的轮次/命令/结果写固定产物（如 `verification-summary.json`），reporting 引用它而非记「验证未执行」；不新增阶段，basic 链保持形状。（对应 S-2）

**P1**

- **I-6 文档型 run 的产出契约**：允许任务声明文档产物校验（存在性 + 结构契约），消除 `validated: null` 空通过。（对应 S-3）
- **I-7 `history list/stats` 只读命令**：清单（时间/项目/状态/时长过滤）+ 汇总统计；本次评估的聚合逻辑可作为其规格。（对应 S-7）
- **I-8 `history doctor` 一致性自检**：检测空目录、zip 缺失、记录重复/孤悬；先修复现存 10 个空目录。（对应 S-8）
- **I-9 runs.jsonl 字段补齐**：追加 `type`/`workflow`/`ephemeral`/`durationSec`（写入口径收归 history.append 一处），旧记录缺字段容忍。（对应全量统计的派生成本）
- **I-10 split 阈值可配 + 违规降级**：阈值作为旋钮（全局/单 run）；超限时静态检查降级为 warning + 用户在确认门显式批准留痕，替代 b4f3 式「失败但放行」。（对应 S-4）
- **I-11 gate 上下文摘要内建**：gate present payload 附当前阶段产物摘要（spec 要点/plan 决策/变更清单），消除 agent 自制确认 prompt 文件。（对应 S-6）

**P2**

- **I-12 none 模式工作区基线**：run start 记录启动时脏文件清单，finish 时输出本 run 净变更 diff。（对应 S-11）
