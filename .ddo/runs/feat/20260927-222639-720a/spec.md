# Eval 评测体系重设计 Spec

> 本文档用于确认 agent 是否正确理解用户关于「检查 eval/showcases 是否过期并设计对齐当前能力面的新评测方案」的需求。

---

## 对齐摘要

- 用户目标：核对现有 showcase（v2-beta，2026-09-24 评估）是否已过期或无法覆盖项目当前评测需要。
- 期望交付：过期核对结论 + 对齐当前能力面的新评测方案设计（落盘形态待 BQ-1 确认）。
- 关键边界：只描述评测体系要什么、为什么；playbook 章节结构、归档操作细节留给 Planning。
- 关键边界：不改内核代码与任务定义，改动限定在 eval/ 及其文档约定。
- 当前状态：存在 3 个会改变交付物与范围的待确认问题（BQ-1/2/3），确认后才能批准。

---

## 用户目标

- 检查现有 showcase 是否「已经过期或者没法满足现在的项目的评测」（用户原话）。
- 明确新评测方案「需要怎么设计」（用户原话）。

---

## 范围与非目标

### In Scope

- 逐维度核对 eval/showcases 现有内容与项目当前能力面的差距，给出过期/覆盖结论。
- 设计新版本评测方案：以 eval/ 既有三目录约定（runs / verify / showcases）为基座的新版 playbook 与配套调整设计。
- 为 pr-delivery 交付链与 WTT worktree 场景设计专项评测用例（可标注执行分期/优先级）。
- 对旧 v2-beta showcase 落盘「已过期、被新版本取代」标注（约定更新的一部分）。
- 若核对结论显示 eval/README 维护约定需要更新，把更新设计纳入交付。

### Non-goals

- 本次不实际执行评测、不产出新 showcase 的运行数据（评测执行留待用户另起 run）。
- 不修改 tools/ 内核代码、atom-tasks 任务定义与 workflows 预设。
- 不做与 eval 无关的仓库清理或文档改版。
