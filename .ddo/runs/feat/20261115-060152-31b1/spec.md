# History 历史查询页面 Spec

> 本文档用于确认 agent 是否正确理解用户关于「在插件中新增 history 历史查询页面，用于搜索过去的决策与关键信息」的需求。

---

## 对齐摘要

- 用户目标：在 ddo-code-flow VS Code 插件中新增一个 history 历史查询页面，用于搜索过去的决策和一些关键信息。
- 期望交付：插件内可用的历史查询页面（页面设计由 agent 主导提出并实现），补足现有历史区「只能浏览、不能搜索」的缺口。
- 关键边界：插件保持只读观测台定位，查询完全基于既有状态文件体系（index / project / history 三源），不要求引擎侧改动。
- 当前状态：无阻塞问题（BQ），等待用户批准。

---

## 用户目标

- 在插件中再提供一个 history 的历史查询页面（插件已具备 history 历史信息的呈现）。
- 页面主要能力：搜索过去的决策和一些关键信息。
- 页面设计由 agent 负责（用户原话「这个你来设计下」，未提供既成设计稿）。

---

## 范围与非目标

### In Scope

- 在插件中新增一个 history 查询页面，作为检索历史信息的新入口。
- 提供按关键词搜索过去 run 的决策记录的能力（决策的构成见「解释与假设」I-1）。
- 提供按关键词搜索关键 run 信息的能力（关键信息的构成见「解释与假设」I-2）。
- 搜索结果可定位到对应的 run，并能查看其详情（复用既有详情呈现能力）。
- 页面的信息架构、搜索交互与结果呈现设计，由 agent 提出并随本次交付落实。

### Non-goals

- 不提供任何控制操作（启动 / 推进 / 收口等），保持插件对状态文件全程只读的既有边界。
- 不修改引擎（CLI）侧的数据写入与数据模型；查询仅消费既有数据源。
- 不替换或移除既有的三区树视图与详情面板；查询页面是新增入口，不是重构。

## 约束与保留术语

- 项目事实约束：插件是只读观测台，对全部状态文件只读、无控制操作（插件 README 声明的角色边界）。
- 项目事实约束：数据面建立在状态文件体系三源之上（`~/.ddo/index.json`、工作区 `.ddo/runs/`、`~/.ddo/history/` 的 runs.jsonl 与 zip 归档）；查询能力应基于这些既有数据，不依赖引擎新增写入。
- 保留用户术语：`history`、`历史查询页面`、`决策`、`关键信息`。

## 解释与假设

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
|---|---|---|---|
| Interpretation（I-1） | 「过去的决策」指历史 run 中记录的确认门决议与相关使用轨迹：门决议选项、门交互反馈全文、呈现时的执行摘要、回滚原因等。 | 引擎数据模型中「决策」的可定位来源为 state 门对象（`gate.decision`）与 `.usage.jsonl` 轨迹事件（`decision` / `interacted` / `presented` / `rollback`）。 | 若用户另指其他决策类信息（如产物文档中的决策记录），搜索对象范围需扩大。 |
| Interpretation（I-2） | 「一些关键信息」指 run 元信息：runId、标题、类型、工作流、finalStatus、起止时间、所属项目等。 | 插件历史区与详情面板既有的关键信息即此类。 | 搜索字段范围需调整。 |
| Interpretation（I-3） | 交付物为设计并实现的新页面（而非仅设计文档）。 | 用户在启动配置中显式选择 feat 类型与含 coding 阶段的 basic 工作流。 | 若用户只要设计文档，coding 交付物会不同。 |
| Interpretation（I-4） | 「history 的历史查询」以历史信息源（全局已收口 run 及归档）为主对象；「过去的」涵盖已结束的 run。具体搜索覆盖面由 agent 在设计中提出、经用户审核。 | 用户表述「我们已经存在了 history 的这些信息了」呼应插件既有历史区；「过去」的自然语义。 | 搜索覆盖范围（是否含运行中 run）在审核时纠正即可，不改变页面存在本身。 |

## 留给 Planning

- PD-1：查询页面的承载形态与入口位置（Webview 独立页面 / 侧边栏内嵌 / 命令面板唤起等）。
- PD-2：搜索的数据访问与索引策略（运行时扫描 runs.jsonl 与 zip 归档 / 预建缓存等）及性能边界（现有历史区 50 条展示上限是否适用于查询页）。
- PD-3：搜索维度的设计取舍（是否增加按类型 / 状态 / 时间过滤、多关键词、结果分组等增强能力）。
