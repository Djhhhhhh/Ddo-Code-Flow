# 项目架构检查 Spec

> 本文档用于确认 agent 是否正确理解用户关于"Ddo-Code-Flow 项目架构检查"的需求。

---

## 对齐摘要

- 用户目标：对 Ddo-Code-Flow 项目进行架构层面、描述一致性和 skill 描述的全面检查。
- 期望交付：检查报告，列出发现的问题和改进建议。
- 关键边界：只检查不修改；覆盖架构解耦、描述一致性和 skill 描述三个维度。
- 当前状态：无阻塞问题，用户确认后可批准。

---

## 用户目标

- 验证 atom-task、workflow、config 三层是否完全解耦，无相互直接依赖。
- 检查单个层变更是否会影响其他层。
- 进行全局描述一致性检查。
- 检查 skill 描述是否存在容易误解或多余的内容。
- 验证关键执行阶段的触发检查是否正常。

---

## 范围与非目标

### In Scope

- 架构解耦检查：atom-task、workflow、config 三层的依赖关系分析。
- 全局描述一致性检查：跨文件的描述是否一致。
- Skill 描述检查：SKILL.md 及相关文档的清晰度和准确性。
- 关键执行阶段触发检查：workflow 中各阶段的触发逻辑验证。

### Non-goals

- 不修改任何代码或配置文件（仅报告发现）。
- 不进行性能测试或安全审计。
- 不检查第三方依赖的质量。
