# PR 格式标准化 Spec

## 对齐摘要

- 用户目标：规范 PR 流水线中的 PR 格式。
- 期望交付：PR 流水线生成的内容遵循统一且可审查的格式。
- 暂定解释：PR 格式涵盖标题与正文，不延伸到提交信息、分支命名或合并策略。
- 用户明确指定标题为 `【type】(scope):<中文摘要>`；正文保留原提案供本次整体审查。
- 当前状态：BQ-1 已按用户回答写回，待用户批准本规格；回答不等同于批准。

## 用户目标

- 将 PR 流水线的 PR 格式标准化。

## 范围与非目标

### In Scope

- 标题采用用户指定的 `【type】(scope):<中文摘要>`；正文按下述五个固定栏目组织（agent 提案，待整体批准）。
- 让 PR 流水线按确认后的格式组织生成的 PR 内容。

### Non-goals

- 不追溯改写已创建的历史 PR。
- 不将提交信息、分支命名、合并策略调整纳入本次格式规范。
- 不额外引入面向所有手工 PR 的强制 CI 检查。

- 保留用户术语：PR、流水线、PR 格式、标准化。

- 标题使用全角方括号 `【】` 包裹 type，scope 使用半角圆括号，使用半角冒号且冒号后不加空格。

## PR 格式约定

- 标题：`【type】(scope):<中文摘要>`；scope 可省略，省略时连同圆括号一起省略；type 使用 `feat / fix / docs / refactor / test / chore / perf / build / ci / revert`。
- 标题示例：`【feat】(deliver-pr):统一 PR 标题与正文格式`；不含 scope 示例：`【docs】:补充使用说明`。
- 正文：固定按 `## 变更摘要` → `## 主要变更` → `## 验证结果` → `## 风险与兼容性` → `## 关联事项` 排列，以中文叙述，代码标识保留原文。
- 变更摘要：一句话说明本次 PR 的目的。
- 主要变更：列出本次实际交付的变化。
- 验证结果：列出真实执行的检查及结果；未执行的检查明确写明未执行及原因，不把计划写成已完成。
- 风险与兼容性：说明已知风险、破坏性变更或迁移要求；不适用时明确写“无已知风险或兼容性影响”，不杜撰风险。
- 关联事项：关联 issue 或相关 PR；无关联时写“无”；普通关联不默认表达自动关闭 issue。
