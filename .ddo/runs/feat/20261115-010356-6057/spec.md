# VS Code 流水查看插件 Spec

> 本文档用于确认 agent 是否正确理解用户关于「创建 plugin 目录并开发 VS Code 插件（图表完全复用 docs/index.html、左侧选择存活流水、右侧查看流水信息）」的需求。

---

## 对齐摘要

- 用户目标：在本项目内新增 `plugin` 目录，开发一个 VS Code 插件，用于查看 ddo-code-flow 的存活流水。
- 期望交付：插件左侧导航栏可选择**全局所有项目中处于运行中状态**的存活流水，右侧工作区展示所选流水的流水信息；插件所有 SVG 图表/图标完全复用 `docs/index.html` 中的样式结构与颜色，不做任何改写。
- 关键边界：本次只做流水「查看」，不做流程控制；`docs/index.html` 仅作为样式来源，不改动其内容；非运行中（已收口等）的流水不进入导航清单。
- 当前状态：BQ-1（存活流水口径）已由用户确认并写回，无未解决问题，等待用户批准本 spec。

---

## 用户目标

- 创建 `plugin` 目录并在其中开发 VS Code 插件。
- 插件所有图表（如 VS Code 左侧的 svg 图标等）完全复用 `docs/index.html` 中的图表样式结构，结构与颜色完全一致，不改变。
- 左侧导航栏可选择存活流水——存活流水指**全局所有项目的运行中 run**（BQ-1 确认）。
- 点击存活流水后，右侧工作区可查看对应的流水信息；信息设计先基于流水结构完成，不符合预期时在 coding 阶段动态调整。

---

## 范围与非目标

### In Scope

- 在项目内创建 `plugin` 目录，承载 VS Code 插件全部工程代码。
- 插件界面使用的所有自定义 SVG 图表/图标完全复用 `docs/index.html` 中对应图表（结构与颜色逐项一致）。
- 插件左侧导航栏：列出**全局所有项目的运行中**存活流水（跨项目，运行中判定以引擎口径为准）供选择。
- 插件右侧工作区：点击存活流水后展示该流水的流水信息（初始设计基于现有流水结构，coding 阶段可按反馈动态调整）。

### Non-goals

- 不在插件内执行流水推进、回滚、收口等流程控制操作（用户未要求，仅做查看）。
- 不改动 `docs/index.html` 的内容（它只作为图表样式复用来源）。
- 不为图标新增主题化、多套配色或其他与「完全一致」相悖的改写。
- 不在导航清单中展示非运行中状态的流水（已收口、未在运行的），也不提供已收口流水的历史管理、检索等能力。

## 约束与保留术语

- 保留用户术语：`存活流水`、`流水`、`流水信息`、`图表`、`plugin 目录`、`完全一致`。
- 用户明确约束：复用 `docs/index.html` 图表时结构与颜色不得改变。
- 用户明确决定（BQ-1）：存活流水 = 全局所有项目的运行中 run。
- 项目事实约束：流水结构以项目 `.state.json` 结构规范（schema v2 六分区：标识 / 环境 / 进度与门 / 编排 / 产物 / 使用日志）为权威，「流水信息」设计以其为依据；「运行中」判定与全局流水发现以引擎现有口径为准。

## 解释与假设

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
|---|---|---|---|
| Interpretation | 「完全复用」指从 `docs/index.html` 复制 SVG 作为插件资源（快照式），而非插件运行时读取该文件。 | 「复用」「不要改变」的最小等价解释。 | 若用户期望随 docs 更新自动同步，插件实现形态不同（当前理解不会自动跟随 docs 后续变化）。 |
| Interpretation | 右侧流水信息的初始设计覆盖 state 六分区中的关键内容（如标识、当前位置、门状态、产物等），具体字段与布局先行设计、coding 阶段可调。 | 用户明确委托「根据我们的流水结构先设计下」。 | 信息取舍与用户预期不符时，按用户预留的机制在 coding 阶段动态调整。 |
| Assumption | VS Code 各图标挂载点能够以原始 SVG 的结构与颜色呈现。 | 用户要求完全一致且未提及平台妥协。 | 若平台对个别位置有强制处理（如单色渲染、尺寸规整），该位置可能无法逐项一致，需回到用户处取舍。 |
