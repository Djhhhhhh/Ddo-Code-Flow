## 背景缺口（2026-09-24 诊断）

1. **无参数 / 参数不合法时行为未定义**：skill 触发后 agent 自由发挥——该问什么、怎么问、按什么数据问，没有协议（与 07 解决「提示不稳定」、08 解决「发现层缺失」同构的问题，这是冷启动版本）。
2. **预设选择无数据面**：有几套预设、各是什么流程，agent 不知道（workflows/ 内容没有命令可读）。
3. **自定义工作流无支撑**：想按需求定制原子任务链，需要快速知道「有哪些原子任务、各做什么」——现在只能全量翻任务文件（违背渐进式加载）。
4. **错误提示不联动发现层**：`run start --workflow 不存在` 只报错不列现有；`exec --task 不存在` 同样不指路。

## 需求输入（2026-09-24，用户）

1. skill 触发时**无参数或参数不合法** → 引导用户做本次工作流的初始化：
   - 是否使用预设工作流；使用则选哪一个；
   - 是否自定义工作流（按用户需求定制原子任务工作流配置）；
2. 支撑自定义需要一个**原子任务注册表**：快速查各个原子任务是做什么的，不需要全量加载任务文件了解信息——**优先通过脚本直接拿到 desc（少维护一个注册表文件）**；
3. 做用户友好的配置；**工作流启动时明确目标是非常关键的事情**。

## 候选机制映射（方向）

| 需求 | 机制候选 |
|---|---|
| 任务 desc 直读 | config.json 增顶层 `desc`（一字段一句描述，schema 纳管）——config 即注册源，不另建文件 |
| 注册表查询 | `list tasks`：读全部 config 派生清单（name/version/desc/相位概要/人审位标记） |
| 预设选择数据面 | `list workflows`：读 workflows/*.json（name/version/description/阶段链概要） |
| 冷启动协议 | SKILL 增「初始化引导」段：①一句话目标 ②预设 or 自定义（数据来自 list 命令）③run 类型 → `run start` |
| 自定义预设 | 引导产出的自定义链写成预设 JSON → `run start --workflows-dir` 指向 |
| 错误联动发现层 | 未知预设 → 报错并列现有（指路 list workflows）；未知任务 → 指路 list tasks |

## 已确认决策（2026-09-24 评审）

| # | 决策 | 依据 |
|---|---|---|
| D1 | **发现命令 = `list tasks` + `list workflows`**（开 list 域，两段式，与 04-D5 预留命名同族；后续 `list history` 自然归位） | 用户定版（Q1） |
| D2 | **自定义链不落预设文件**：引导拼链 → 写临时预设 JSON（tmpdir）→ `run start --workflows-dir` 指向 → 物化进 `.state.json` 即自包含，临时文件用后即弃。**预留概念（本轮不做）**：结束后脚本把 state 归档到 `~/.ddo/history`，以「同类自定义链出现频次」驱动预设自我进化——归产物生命周期轮 | 用户定版（Q2） |
| D3 | **引导最小集**：①目标一句话（title）②预设 or 自定义（选择时用 list 命令数据呈现）③run 类型；**run start 物化时预标记可配置项**——把 workflow 内任务声明的 configurable 默认值预填进 `state.atomTasks`，用户打开 state 即知可改哪些 | 用户定版（Q3） |
| D4 | **desc/configurable 进 config.json**（schema 纳管）——config 即注册源，脚本直读，不另建注册表文件 | 用户定版（需求输入 2） |
| D5 | **错误联动发现层**：未知预设 → 报错并列现有（指路 list workflows）；任务不存在 → 指路 list tasks | 方向定（需求输入 4） |
| D6 | 现有真实旋钮盘点：`test-plan.tdd`（可预填 default）、`create-pr/remote-gate.issueNumber`、`issue-fetch.repo`（无默认，仅呈现不预填） | 实现期盘点 |
