# 工作项 08 · resume — 断点重续入口（工作流中间状态加载）

> 状态：**需求定版（D1–D3，2026-09-24）**，实现中

关联：

- [../07-exec-loop/plan.md](../07-exec-loop/plan.md) v1.4 —— `status` 是单 run 细节视图；本轮补它的**发现层**（不知道 statePath 时的入口）

## 背景缺口（2026-09-24 诊断）

工作流天然支持断点重续（state 自包含、`currentStage` 精确到相位、status 有细节视图），**但缺加载指令**：

1. 新会话续跑时，agent 只能自己读 `~/.ddo/index.json` 人肉解析——无结构化命令，续跑入口不稳定（与 07 解决「提示不稳定」同构的问题）；
2. index 的惰性校验（02 §7：statePath 失效不展示）没有执行方；
3. 多项目并发发现（v2 主线目标）无操作面。

## 需求输入（2026-09-24，用户）

1. 新增**工作流中间状态加载指令**；
2. 工作流应天生支持断点重续——命令只做定位与呈现，续跑动作仍归既有命令集（exec/next/门决议）。

## 候选机制映射（方向）

| 需求 | 机制候选 |
|---|---|
| 中间状态加载 | `resume`：读 DDO_HOME 下 index → 惰性校验 → 列运行中 run（含位置/门概要）；选定后输出完整 status 视图（复用 07 的双清单） |
| 断点重续 | 选定 run 后 `availableCommands` 已给出下一步（exec/门决议/收束）——agent 按清单继续，无需新语义 |
| 多项目发现 | 全局 index 为源，每条标注项目根；可选 `--project` 过滤 |

## 已确认决策（2026-09-24 评审）

| # | 决策 | 依据 |
|---|---|---|
| D1 | **命名 `resume`，顶层动词**（03 §3.4 自足原语，宾语隐含「运行中的 run」）；语义 = 断点重续的发现与加载入口，只定位与呈现，续跑动作归既有命令集 | 用户定版（Q1） |
| D2 | **无参默认全局清单**：读本机 index 全部运行中 run（每条标注项目根），`--project <path>` 可选过滤——worktree 场景不漏，直接服务 v2 多项目并发发现主线 | 用户定版（Q2） |
| D3 | **一律先列清单**：无论候选数，无参只输出概要清单；选定用 `resume --run-id <id>` 取完整状态视图（与 status 同构）——行为始终一致 | 用户定版（Q3，覆盖单候选直出建议） |
| D4 | 惰性校验（02 §7 落地）：statePath 缺失/结构非法 → 不展示（计 staleCount）；**细化**：currentStage 空且结构合法 → 标记「待收束」仍展示（否则无法发现并收束） | 方向定（随 plan） |
| D5 | resume 不收 `--state`——知道 statePath 就用 `status`；resume = 发现层（index 驱动），status = 细节层（statePath 驱动），职责分明 | 设计推导 |
