# 工具降级问询能力 Spec

> 本文档用于确认 agent 是否正确理解用户关于「宿主 agent 无提问工具时，问询环节降级为直接文本问询」的需求。

---

## 对齐摘要

- 用户目标：以「宿主是否自带提问工具能力」的检测结果为开关：检测到则用提问工具，检测不到则问询降级为文本一问一答，流程不再停滞等待该工具。
- 期望交付：流程指令内容自带该检测与降级规则，覆盖所有要求宿主提问工具的问询环节（启动问询、人工审核门、相位内问询、人工检查项确认）。
- 关键边界：有提问工具的宿主保持原方式；降级只改变问询的呈现与答复方式，不改变各选项的动作语义与决议机制。
- 当前状态：BQ-1 已按用户答复解决（覆盖全部问询环节，机制为能力检测），待用户批准。

---

## 用户目标

- 流程先检查宿主 agent 是否自带提问工具能力；检测不到该能力时，问询降级为文本形式的一问一答，以取得用户决议，流程不因缺少该工具而卡死或要求用户下达特例指令解锁。
- 保留用户术语：宿主提问工具、降级、问询、人工审核门、一问一答。

---

## 范围与非目标

### In Scope

- 为流程补充「检测宿主提问工具能力，检测不到则降级为文本一问一答」的指令规则，覆盖所有要求宿主提问工具的问询环节：启动分流与 guide 启动问询、人工审核门决议、相位内问询、人工检查项逐项确认。
- 降级问询中取得的用户文字决议与经提问工具取得的决议同等分发执行（如文字回复"同意"即按同意推进）。

### Non-goals

- 不改变各审核选项的动作语义与 CLI 的决议、推进、状态机制本身。
- 不新增提问工具或替代工具；宿主已提供提问工具时不触发降级。
- 不擅自改动 `~/.claude/skills` 下的安装副本或发布/安装流程（见解释与假设中的假设条目）。

## 约束与保留术语

- 保留用户术语：`宿主提问工具`、`降级`、`问询`、`人工审核门`、`一问一答`。
- 决议有效性约束（源自问题现状记录）：`继续` 等普通文字不得视为对送审内容的明确批准；降级问询下同样只有明确的选项答复才是决议。
