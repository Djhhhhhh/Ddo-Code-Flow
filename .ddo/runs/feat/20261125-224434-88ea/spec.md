# model-quick-eval 评测流水线 Alignment Spec

> 本文档用于确认 agent 是否正确理解用户关于「实现 eval/bench/model-quick-eval 模型能力评测流水线」的需求。

---

## 对齐摘要

- 用户目标：为 Ddo-Code-Flow 建一条 `model-quick-eval` 快速评测流水线，对同一模型跑 A/B 双分支（纯 prompt vs prompt + Ddo-Code-Flow），自动提取结果层、过程层、成本层数据，输出对比卡片与汇总报告。
- 期望交付：`eval/bench/` 目录下的评测 subflow、题库、探针脚本、报告模板、auto 模式支持与 prompt 修正规则库，按需求 §11 DoD 验收。
- 关键边界：目标是快速形成体感并支撑对外宣传，不是全面测评；小样本属性必须标注；负增益与无差异如实记录；token 仅用于同模型 A/B 对照。
- 当前状态：BQ-1（subflow 实现形态）已按用户决议写回（混合形态：引擎仅补足必要能力，编排在 `eval/bench/`），无未解决 BQ，等待用户批准。

## 用户目标

- 实现名为 `model-quick-eval` 的 subflow：输入新模型标识与 2–3 道题，自动跑 A/B 双分支，自动提取结果层、过程层、成本层数据，输出对比卡片与汇总报告。
- 评测主体是模型，产物是两种条件下模型表现的对照；目标是快速形成体感并支撑对外宣传，不是全面测评。
- 保留用户术语：`subflow`、`A/B 双分支`、`baseline` / `ddo`、`冻结核心集`、`可澄清项清单`、`隐藏验收`、`工作流敏感型`、`auto 模式`、`cc-switch`、`达标项/总项`、`prompt.diff`。

## 范围与非目标

### In Scope

- §8 五步流水线：准备沙箱 → 并行执行 A/B 双分支 → 收集与提取 → 自动判定与量化 → 生成报告。
- 题库体系（§3/§4）：题位结构（题 1 页面必备、题 2 调研依赖/回归陷阱轮换、题 3 可选）、核心集 + 当轮新增题选取规则、防污染规则、题目入库。
- 页面题（Three.js）Playwright 探针与多视口截图量化验收（§4.1 隐藏验收清单 A1–F1）。
- 非页面题量化提取：design 线路（`q_export-command`）与 execute 线路（`q_regression-trap`）至少各 1 道入库并跑通。
- 过程层 5 个信号 + 澄清对称性的提取与负面计数指标（§5.2）。
- 成本层：token 统计走 cc-switch 代理日志，按 session_id 聚合，按组/按题/按阶段产出（§5.3）。
- auto 模式：gate/澄清应答来自冻结清单、中性只推进、可记录、可关闭（保留 manual 对照）；baseline 侧对等自动应答通道（§7）。
- prompt 修正双层规则：`prompt-rules.md` 规则库、`prompt.diff` 生成与人工复核流程、冻结产物（§6）。
- 报告模板：每题对比卡片（直观区 + 量化区 + token 行）+ 汇总页（§9）；`rubric.md` 评分细则（§10）。
- 产物按 §10 目录结构在 `eval/bench/` 下落位。

### Non-goals

- 不做全面测评或大规模 benchmark；不产出跨模型可比结论（token 跨模型不可比）。
- 不为 ddo 增益做包装：结果层不做加权总分，不合成单一性价比分数，负增益/无差异不剔除、不美化。
- 不修改入库题目的冻结 prompt 原文（如 `q_threejs-orbit-scene` 的 12 条要求 prompt）。
- 不在本轮要求题库全部题目「跑通」：本轮必须跑通的是 DoD 所列三道（页面题 + design + execute 各 1 道）；其余题目（另两道页面题、题 3 可选题库）作为题库登记项落地结构即可（见解释与假设 INT-2）。
- 不将「过于简单的任务」纳入正向结论（诚实边界，§2）。

## 约束与保留术语

- 硬性约束（用户标注「必须」「禁止」，不得自行放宽）：§1 全部 7 条（控变量、信息对等、不替决策、工作流敏感型题目、诚实记录、小样本标注、token 不进工作流内部）。
- 版本锁定：页面题 `three@0.160.0`，探针按该版本字段编写；CDN 放行 `unpkg`，单文件 `index.html` 直接打开渲染。
- session 约束：强制 `baseline_sid ≠ ddo_sid`，执行前校验；cc-switch 路由与「记录请求用量」开启为环境前提。
- 形态约束（BQ-1 决议）：评测编排在 `eval/bench/`，引擎仅补足评测必需能力（如 auto 模式），不做评测专属的侵入式扩展。
- 冻结约束：`q_threejs-orbit-scene` 等题目 prompt 原文冻结，不得修改；修正模型与被测模型不得同源（用固定第三方 judge）。
- 保留术语见「用户目标」第三条。
