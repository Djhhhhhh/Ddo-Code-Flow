两层拆分（引导执行层 / 引擎层）＋ 子流程分层编排（运行期创建 · 阻塞式 · 最多三层）· plan revision 1 审阅稿

① 两层架构 — 引导执行层 ⇄ 引擎层（解耦契约）
② 动态编排示例 — 状态如何一步步转化（父 run · plan 相位下沉调研子流程；分层静态视图见 ③）
任务相位状态机（每个 stage） pending→ running⇄ waiting-human（门）→ done 子流程生命周期 active→ closed（终态校验 / --abandon）
1启动父 run Arun start --workflow basic --title …
父 .state.json（depth=1）
{
  "runId": "20261031-170400-b679",
  "currentStage": ["requirement:01"],
  "stages": { "requirement": { "status": "running" },
              "spec": { "status": "pending" }, … },
  "subflows": （无——可选段缺省）
}
说明
物化 basic 链全部 pending；无依赖的 requirement 点亮。
此刻没有 subflows 段——旧语义，与升级前完全一致。
2A 沿链推进到 plan（多轮 exec → validate → next / gate 同意）next --decision 同意（spec 门）…
父 .state.json
{
  "currentStage": ["plan:01"],
  "stages": { "requirement": { "status": "done" },
              "spec": { "status": "done", "gate": { "decision": "同意" } },
              "plan":    { "status": "running" } }
}
说明
next 纯状态推进：相位内走相位号，相位耗尽则 stage=done 并按 DAG 点亮后继；human 相位开确认门，决议后留痕关闭。
3plan 执行中发现调研细节 → 运行期创建子流程并下沉subflow start --state <父> --at plan --title 调研X
父 .state.json
{
  "currentStage": ["plan:01"],
  "subflows": [ { "id": "sf-1", "atStage": "plan",
    "statePath": "<runDir>/subflows/sf-1/.state.json",
    "status": "active", "startedAt": "…" } ]
}
子 .state.json（新物化，depth=2）
{
  "runId": "20261031-170400-b679-sf1",
  "currentStage": ["requirement:01"],
  "dirs": { "runDir": "<父runDir>/subflows/sf-1" },
  "subflow": { "depth": 2, "parentStatePath": "…",
               "atStage": "plan" }
}
4阻塞式：active 子流程存在期间，父流程被拦截next --state <父> → exit 1
父 .state.json（不变）
{ "currentStage": ["plan:01"],  /* 原地不动 */
  "subflows": [ { "id": "sf-1", "status": "active" } ] }
CLI 响应（stdout JSON + stderr 人话）
{ "blocked": "subflow-active",
  "subflows": [ { "id": "sf-1", "status": "active",
                  "statePath": "…" } ] }
stderr: [子流程未收口] sf-1 active——
        先完成子流程并 subflow close
5子流程 B 按正常流水逻辑执行（与父完全同构的循环）exec / validate / next --state <子> …
子 .state.json
{ "currentStage": [ ],
  "stages": { … "reporting": { "status": "done" } } }
/* next 返回 completed: true —— 子流程终态 */
说明
子流程内部照常经历 running / waiting-human（门）/ done；孙流程同理再下沉一层（depth=3，上限拒绝第 4 层）。
6收口留痕：close 校验终态，父流程解除阻塞subflow close --state <父> --id sf-1
父 .state.json
{
  "subflows": [ { "id": "sf-1",
    "status": "closed", "closedAt": "…" } ]
}
/* 之后 next --state 父 恢复正常推进 */
说明
close 读子 state 校验 currentStage 为空（或 --abandon 跳过校验并标 abandoned）；B、C 多子流程须全部 closed 后父才可推进。
7链尾完成与归档run finish --state <父> --status done
收口检查
/* finish 前置校验：无 active 子流程
   （否则 exit 1 提示先 close/abandon） */
落盘
runDir 整目录 zip → ~/.ddo/history/<runId>.zip（天然包含 subflows/sf-1 及其产物）＋ runs.jsonl 记录；子流程不入全局 index、不单独归档。
