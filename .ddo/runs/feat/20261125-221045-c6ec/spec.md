# ~/.ddo 本地注册源缺省合并发现 Spec

> 本文档用于确认 agent 是否正确理解用户关于「CLI 缺省合并解析 `~/.ddo/` 用户本地注册的自定义流程」的需求。

---

## 对齐摘要

- 用户目标：新会话（尤其非 Claude Code 宿主）输入 `ones-d` 等本地注册流程名时零搜索直接启动，消除每次启动的翻找/全盘搜索成本。
- 期望交付：`list` / `guide` / `run start` 的预设与任务目录解析缺省合并检查 `~/.ddo/workflows/` 与 `~/.ddo/atom-tasks/`。
- 关键边界：合并为加性、不遮蔽内置预设、同名冲突 fail-fast；未部署 `~/.ddo` 的机器行为与现状完全一致。
- 当前状态：BQ-1 已决议（profiles 不纳入缺省自动发现），无未解决阻塞问题，等待用户批准本 spec。

---

## 用户目标

- 让本地注册的自定义流程（`ones-o` / `ones-d` 等）成为引擎缺省可发现的加载源，替代「被动可发现性」绕法（`~/.ddo/README.md`、项目 `.ddo/CUSTOM-FLOWS.md`、宿主记忆）。
- 新会话输入 `ones-d` 启动时，`list workflows` 直接可见、guide 一步命中、`run start` 按注册目录解析，全程零搜索。
- 保留用户术语：用户本地注册目录（`~/.ddo/`）、预设（workflow）、原子任务（atom-task）、profiles、fail-fast、遮蔽（shadow）。

---

## 范围与非目标

### In Scope

- `list workflows` 不带参数即列出内置预设与 `~/.ddo/workflows/` 本地注册预设的合并结果。
- `guide` 模式选择输入本地注册流程名（如 `ones-d`）一步命中，并按注册目录解析启动。
- `run start` 的预设解析与任务目录解析缺省合并检查 `~/.ddo/workflows/` 与 `~/.ddo/atom-tasks/`。
- 合并语义：加性、同名冲突 fail-fast、不遮蔽内置预设。
- 未部署 `~/.ddo`（或注册子目录不存在）时行为与现状完全一致。

### Non-goals

- 不修改 skillRoot 内容与内置预设本身（项目红线）。
- 不新增 `~/.ddo` 注册目录的创建/管理命令（注册结构已由此前 run 交付，本次只做加载发现）。
- 不扩展用户未点名的其他命令（如 `list tasks`）的合并行为（agent 解释，见解释与假设）。
- 不变更 state schema（用户初判：启动时解析，不落新字段）。
- 不将 `~/.ddo/profiles/` 纳入缺省自动发现：profiles 保持纯文件引用（经 atom-tasks prompt 引用路径），引擎不感知（BQ-1 决议）。

## 约束与保留术语

- 保留用户术语：`~/.ddo/`（用户本地注册目录）、预设（workflow）、原子任务（atom-task）、profiles、fail-fast、遮蔽（shadow）、`ones-o` / `ones-d`。
- 项目事实：本机 `~/.ddo/` 已有可用注册结构（`workflows/*.json` + `atom-tasks/<task>/{config.json,prompt.md}` + `profiles/*.json`），直接作为加载源与验收样例。
- 项目事实：此前已批准设计（记忆 `ddo-user-local-loading-source`）——`~/.ddo/atom-tasks` + `workflows` 注册 + `lib/sources.js` 合并解析。
- 用户初判约束：state schema 预计不变（启动时解析，不落新字段）；若实现证明需要变更，应在 plan 阶段显式说明依据。
- 项目红线：不修改 skillRoot、`.gitignore` 或 git exclude。
- 用户决议（BQ-1）：`~/.ddo/profiles/` 不纳入缺省自动发现，保持纯文件引用、引擎不感知。

## 解释与假设

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
|---|---|---|---|
| Interpretation | 「同名冲突 fail-fast」覆盖两类冲突：本地 vs 内置同名、本地 vs 本地同名；fail-fast 指解析/启动阶段即报错退出。 | 与「不遮蔽内置」联合读取为同一合并语义。 | 若用户只想检测其中一类，FR-5 与 AC-4 的判定范围变化。 |
| Interpretation | 「未部署 `~/.ddo`」指注册子目录（workflows / atom-tasks）不存在或为空；`~/.ddo` 因 tmp 等其他用途存在不影响等价性判定。 | `~/.ddo` 已承载临时模式运行材料，目录存在≠注册了流程。 | AC-5 的验证口径变化。 |
| Interpretation | 命令范围限定为用户点名的 `list` / `guide` / `run start`；`list tasks` 等其他命令本次不扩展合并。 | 用户明确列举了三个命令，保守收窄不扩写。 | 若用户期望 `list tasks` 同步合并，范围扩大（可通过修改反馈加入）。 |
| Assumption | 本机已注册的 `ones-o` / `ones-d` 结构无需迁移即可被新解析加载。 | 用户陈述其为前一 run 的交付产物且「可直接作为加载源与验收样例」。 | 若结构与解析不匹配，需先修注册结构，交付面扩大。 |
