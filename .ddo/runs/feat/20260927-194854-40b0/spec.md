# 交付链收口设计 Spec

> 本文档用于确认 agent 是否正确理解用户关于「交付链收口顺序/职责归属设计」的需求。

---

## 对齐摘要

- 用户目标：消除交付链「cleanup-worktree 删除 worktree × run finish 唯一收口」的顺序冲突——收口保证由机制承载，不再依赖人工记住绕行顺序。
- 期望交付：交付链结束时 run 已被正式收口（链内默认免归档）、run 产物随分支入库、worktree 照常清理（本地/远程分支保留）。
- 关键边界：合并确认门语义、清理语义（留分支）不变；不引入装配层机制改动以外的隐含行为。
- 当前状态：BQ-1（链内默认免归档）、BQ-2（产物随分支入库）已决议写回，待批准。

---

## 用户目标

- 交付链（pr-delivery / pr-delivery-issue）走完时，run 的收口（index 注销、终态记录）是链内结构性保证，而非人工按正确顺序操作的前提。
- 「这个问题比较大……需要设计一下」——期望一次正式设计轮，而非任务文案级补丁。

---

## 范围与非目标

### In Scope

- 交付链收口顺序/职责归属的设计与落地：run 在 worktree 移除前完成正式收口，或等价的结构保证。
- run 产物在收口路径上的归宿明确（进 git 或显式丢弃，依 BQ-2）。
- 两条交付预设与相关任务的必要调整。

### Non-goals

- 不改变合并确认门（人工确认合并）与清理语义（worktree 删除、本地/远程分支保留）。
- 不动开发链（basic / standard）的收口行为。
- 不引入「原子任务启用开关」等装配层机制。
- 不做 history 查询/清理命令。

## 约束与保留术语

- 项目事实：`run finish` 是唯一收口入口（清 currentStage、index 注销、可选归档）；`--no-archive` 旗标已存在（PR #55）。
- 项目事实：cleanup-worktree（新拓扑版）要求「先切回主检出再移除」；两条实链 run 均靠人工绕行收口（commit 产物 → finish → remove）。
- 保留术语：收口（run finish）、绕行顺序、账本（.state.json）、主检出。
