# RunId 目录创建可配与 State 居所 Spec

> 本文档用于确认 agent 是否正确理解用户关于「runId 目录创建可配置与 `.state.json` 居所设计」的需求。

---

## 对齐摘要

- 用户目标：为「过程信息无需保留」的 run（如 PR workflow 场景）提供可配置的临时模式——运行材料整体落用户主目录下的 tmp 区域，执行完成后直接删除；正常 run 完全保持现状。
- 期望交付：临时模式的配置能力，含 `.state.json` 在该模式下的居所（随运行材料在 tmp）与删除语义。
- 关键边界：`.state.json` 唯一事实源契约不动摇；正常模式行为零变化；缺省即正常模式，临时模式 opt-in。
- 当前状态：BQ-1～BQ-3 已全部解决并写回，等待用户批准。

---

## 用户目标

- PR workflow 等场景下，每次 run 额外创建的 runId 目录增量太快，这类过程信息本质上不需要保留——用户原话「每次生成这个都会额外创建一个 runId 的目录，这个增量太快了」。
- 正常 run 的产物与 `.state.json` 保持现状（随项目入版控）——用户澄清「我的期望是正常入版控的」+ BQ-2 答案「保持现状」。
- 是否创建（项目内 runId 目录）由配置控制——用户澄清「期望需要可以配置是否要创建」。
- 无需保留的场景，运行材料可落用户主目录下的 tmp，执行完成后直接删掉临时文件——BQ-1 答案原话。
- `.state.json` 无论如何必须创建（run 运行的前提），其在该场景下的居所要经过设计——用户澄清原话。

---

## 范围与非目标

### In Scope

- 临时模式完整语义：运行材料（含产物与 `.state.json`）居所移至用户主目录下 tmp 区域、项目内不创建 runId 目录、run 结束后临时文件直接删除。
- 模式的配置入口（选择正常 / 临时模式）。

### Non-goals

- 不改变正常模式的任何行为——现状即契约（runId 目录、产物与 state 同址入版控）。
- 不重构 `~/.ddo` 全局层（index.json / history / zip 归档机制本身）。
- 不提供存量 runId 目录的清理 / 迁移工具——本次只定义增量行为。
- 不改 WTT（worktree 创建时机）机制本身——仅文档化临时模式引入的不变量例外。

## 约束与保留术语

- 保留用户术语：`runId 目录`、`.state.json`（唯一事实源）、`产物`、`版控`、`tmp`（用户主目录下的临时区域）。
- 术语映射：用户触发语中的「runs 信息」指「run 的运行材料」（runId 目录内全部内容，含产物与 state）。
- 项目事实约束：runDir ⊂ projectRoot 不变量在临时模式下出现显式例外（运行材料移居项目外）；state.dirs 显式携带 projectRoot / runDir / worktreePath，机械上支持重定位，例外需在实现中文档化。
- 项目事实约束：产物声明为 runDir 内相对路径、禁绝对路径与 `..`（防逃逸）——runDir 换址后规则同样适用。
- 项目事实约束：中断恢复依赖 `~/.ddo/index.json` 的 statePath 全局指针——临时模式下该寻址照常工作。
