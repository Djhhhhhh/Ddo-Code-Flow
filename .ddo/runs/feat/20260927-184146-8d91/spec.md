# PR 交付收尾 Workflow Spec

> 本文档用于确认 agent 是否正确理解用户关于「新增一条交付收尾 workflow：push → 指定合并目标建 PR → 合并确认 → 清 worktree 保留远程分支」的需求。

---

## 对齐摘要

- 用户目标：新增交付收尾 workflow，串起 推送分支 → 创建正式 PR（可指定合并目标分支）→ 用户确认 PR 已合并 → 移除本地 worktree 但保留远程分支；并按是否绑定 issue 提供主链与变体链两条预设。
- 期望交付：两条预设（主链 + issue 变体链）与净新增 2 个单一职责任务（PR 交付任务、link-issue），复用 `cleanup-worktree`；现有 basic / standard 预设不受影响。
- 关键边界：workflow 不执行合并（合并确认走人工确认门）；不删除远程分支；主链不含任何 issue 逻辑；不引入「阶段启用开关」机制。
- 当前状态：BQ-1、BQ-2 已决议写回；issue 绑定方案经提问轮收敛为「2 任务方案」并已写回，待批准。

---

## 用户目标

- 以新增的 workflow 预设承载完整交付收尾动作：git push、创建指定合并到哪个分支的 PR、检查 PR 合并、移除本地 worktree 并保留远程分支。
- 大部分场景不绑定 issue（主链零 issue 环节）；少数需绑定 issue 的场景通过变体链获得 PR↔issue 关联能力。
- 保留用户术语：workflow（本仓库语境指 `workflows/<name>.json` 预设）、worktree、PR、合并目标分支、远程分支。

---

## 范围与非目标

### In Scope

- 新增交付收尾 workflow 预设两条：主链覆盖 推送特性分支 → 创建正式 PR（可指定合并目标分支）→ 人工确认合并 → 移除本地 worktree（保留远程分支）；issue 变体链在此基础上增加 PR↔issue 关联环节。
- PR 创建时合并目标分支可指定。
- worktree 的移除以「用户确认 PR 已合并」为前置条件。
- 新增任务遵循单一职责：issue 逻辑不混入主链任务。

### Non-goals

- 不改动现有 basic / standard 两条预设的阶段链与既有行为。
- 不改造 create-pr / issue-fetch / remote-gate 等既有任务的行为。
- 不引入「原子任务启用开关」等装配层机制改动（可选性由预设选链表达）。
- 不自动执行 PR 合并（仅呈现状态并等待人工确认）。
- 不删除远程分支。
- 不包含 requirement → coding 等开发前置阶段（本预设面向「特性分支已完成」后的收尾场景；若需拼接开发链，请用「修改」提出）。

## 约束与保留术语

- 用户明确约束：远程分支保留，任何清理动作不得删除远程分支。
- 用户明确约束：worktree 移除必须发生在 PR 合并确认之后。
- 用户明确约束（BQ-1 决议）：PR 以正式（ready）状态创建，不走 draft。
- 用户明确约束（BQ-2 决议）：合并确认采用人工确认——呈现 PR 信息，用户确认「已合并」后继续，不做自动轮询等待。
- 用户明确约束（修改轮）：合并确认门作为 human 相位承载于 PR 交付任务内；不新建独立 merge-confirm 任务，push 也不独立成任务（单一职责的切分线划在 issue 边界）。
- 用户明确约束（修改轮）：issue 关联的 issue 号显式提供，不从分支名推断。
- 项目事实：`create-pr` 任务已支持 `baseBranch`（合并目标，缺省主分支）与 `draftPR`（缺省 draft）配置；`cleanup-worktree` 任务移除 worktree、默认保留本地分支、不触碰远程，且已有「不得在被清理目录内执行删除」的约束。复用或改造由 Planning 决定。

## 解释与假设

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
|---|---|---|---|
| Interpretation | 「检查pr合并后」指 workflow 核对 PR 的合并状态（merged）后再清理，workflow 本身不执行 merge 动作。 | 原文动词为「检查」，且与 Non-goal「不自动合并」一致。 | 若用户实际期望自动合并 PR，交付物会增加合并行为，需重新界定 FR-CHECK-1。 |
| Interpretation | 「移除本地worktree」仅指移除工作树目录；本地分支引用默认保留（沿用 `cleanup-worktree` 现有缺省，仅用户明确要求时删除）。 | 用户以「本地 worktree / 远程分支」为对照；项目现状默认保留本地分支。 | 清理后本地分支引用比预期多留（或少删）一条，用户可明确要求调整。 |
| Assumption | 本预设面向「特性分支开发已完成」后的收尾场景，链路起点是已完成分支，不含开发前置阶段。 | 用户描述的全部动作均为交付动作，且用词「额外」表明与现有开发链并存。 | 若用户期望内置开发阶段，预设范围显著扩大，需重写范围与阶段链。 |

## 留给 Planning

- **PD-1**：方案已收敛——净新增 2 任务（PR 交付任务：action 相位「push + 建 ready PR + 产出 pr-info」+ human 相位「合并确认门」；link-issue：单一关联职责），复用 `cleanup-worktree`；剩余细节为两条预设 JSON 的命名与阶段依赖、link-issue 与合并确认门的先后顺序、`Closes #N` 写入 PR 正文的时机。
- **PD-2**：合并目标分支的传入方式（预设 configurable 旋钮 / 启动参数 / 执行时询问）与缺省值。
- **PD-3**：清理自身所在 worktree 时的会话目录切换处理（如何套用 `cleanup-worktree` 既有约束）。
