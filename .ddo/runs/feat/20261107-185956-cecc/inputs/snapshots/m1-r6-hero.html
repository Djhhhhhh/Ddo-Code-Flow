01 · 定位

这是什么

直接让 AI 完成开发任务，容易出现「需求尚未对齐就开始实现」「方案没有审核」「过程缺少留档」「中断后无法接续」。 Ddo-Code-Flow 把任务组织成可审核、可恢复的流程，并用一个零依赖的 Node CLI 检查执行位置、输出契约与确认门。

CLI 组织
提供当前指令、校验产物、检查位置与确认门、推进状态。
不代替代理完成任务，不代替用户决议。
代理 执行
完成当前指令要求的工作，校验产物，呈现选项并执行合法命令。
不手改 state，不自造选项，不替用户批准。
用户 决议
显式调用、选择配置、审核关键交付并作出决议。
不需要手动操作内部状态文件。
02 · 特性

要解决的问题，与它给的机制

需要解决的问题提供的机制
需求和方案缺少审核工作流中的人工审核点；呈现与用户决议留痕
一次加载全部指令和历史每个相位按当前状态组装指令、配置、上下文和输出契约
代理只口头声称完成通过 validate 检查声明的产物
重做时新旧产物混在一起阶段回滚，失效产物移动到 _del/
会话中断后失去执行位置.state.json 保存状态，resume 接续
Dogfooding — 本仓库 v2 的需求与定版方案保存在 .ddo/runs/feat/ddo-code-flow-v2/，开发过程也使用了这套流程。
03 · 工作流

内置工作流与阶段链

basicstandardtestpr-deliverypr-delivery-issue
basic
轻量开发链：requirement → spec → plan → coding → reporting。
standard
完整开发链：增加测试计划、任务拆分、验证、复审和复盘。
test
测试链路：test-scope → test-design → test-unit / api / e2e → test-reporting。
pr-delivery
PR 交付收尾链：deliver-pr → closeout-worktree。
pr-delivery-issue
交付链的 issue 关联变体，增加 link-issue。
自定义
列出任务，与代理确定阶段及依赖，再通过临时预设启动。

阶段链支持 DAG 依赖。next 推进所有当前位置；一轮多个普通执行位置须全部校验成功后再推进；一次 next --decision 将同一决议用于所有当前确认门。

04 · 工作原理

普通执行循环

1读取完整 currentStage，每个当前步骤先通过 exec 获取本次指令。
2完成本轮所有普通执行位置的实际工作。
3分别 validate；任一未完成或未通过校验，不调用推进命令。
4无审核时统一执行一次 next；有审核时按 gate payload 呈现，等待用户决议。
5每次状态改变后重新读取位置；全部完成后执行 run finish。
概念含义
原子任务atom-tasks/<name>/ 任务单元，含指令、相位与产物声明
workflow 预设声明阶段及 dependOn，启动时物化进 state
run一次运行，含任务链、状态和流程产物
相位任务中的步骤，位置以 spec:01 表示
确认门人工审核位置，获明确决议后才能推进
子流程运行期下沉的嵌套流水，深度最多三层

相位内修改、提问或回答问题不等于批准；交互先通过 gate interact 留痕，处理后重新 gate present。

05 · 命令参考

CLI 命令一览

统一入口 node "<skillRoot>/tools/cli.js" <命令>；日常由 SKILL.md 调用，下表供手动调试与维护参考。

命令作用
guide返回运行清单、完整启动问题、选项和参数映射
run start按预设创建 state 并注册运行；支持 --ephemeral
exec / validate返回当前相位组装指令 / 检查产物与输出 schema
next / rollback推进全部位置 / 重置阶段（旧产物移到 _del/）
gate present / interact呈现审核选项 / 记录相位内交互
subflow start / close创建 / 收口子流程
run finish结束运行并移出运行索引
status / resume查看位置与可用命令 / 恢复运行
list tasks / workflows列出任务与相位 / 预设与阶段链
