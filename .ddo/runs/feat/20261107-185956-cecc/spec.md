## 对齐摘要

- 用户目标：为仓库新增 `docs/` 目录承载项目介绍页 HTML，并优化 README 的组织逻辑（issue #85）。

- 关键边界：coding 阶段对介绍页按模块执行「修改问询与建议 → 用户反馈 → 修复该模块 → 用户验收 → 下个模块」循环；README 按常规阶段执行。
- 诚实性要求：介绍页内容须诚实可信、突出项目真实特点，事实性描述与仓库实际一致，不存在较大偏差。

## 范围与非目标

### In Scope

- 新增 `docs/` 目录，交付项目介绍页 HTML（以 issue #85 最新草稿为基线，8 模块、自包含单文件）。
- coding 阶段对介绍页执行逐模块「问询建议 → 用户反馈 → 修复单模块 → 用户验收」循环。
- 介绍页事实性内容与仓库实际比对与修正（版本徽章、运行目录名、命令行为、工作流链、机制描述等）。
- README 结构与逻辑优化（以 issue 评论 1 草稿为基线），并创建其引用的 `docs/header.svg`。

### Non-goals

- 不修改 skill 引擎行为（`tools/`、`atom-tasks/`、`workflows/` 的代码与配置）。
- 不做 GitHub Pages 等站点部署或在线托管。
- 不重写介绍页视觉风格基线（Neon Cyber 终端风、竖向翻页保持；变更只能来自逐模块循环中的用户决议）。
- 不为介绍页引入构建工具链或运行时依赖（草稿为自包含单文件 + 字体 CDN）。
