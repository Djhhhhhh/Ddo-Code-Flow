# docs/index.html 移动端适配 Spec

> 本文档用于确认 agent 是否正确理解用户关于「@docs/.html 进行移动端适配」的需求。

---

## 对齐摘要

- 用户目标：docs 目录下的介绍页（docs/index.html）在手机等移动端设备上可正常浏览。
- 期望交付：对该 HTML 页面完成窄屏适配；移动端不合理的排版采用异化的移动端排版逻辑，由 agent 整体设计。
- 关键边界：PC（桌面端）展示完全不受本次修改影响；不重做视觉风格、不改变文案内容。
- 当前状态：无阻塞问题（BQ），已按用户修订更新（见对齐变化摘要），等待用户再次批准。

---

## 用户目标

- 让 docs/index.html（项目介绍页，竖向全屏翻页形态）在移动端获得正常、完整的浏览体验。
- 移动端排版不必沿用桌面逻辑：不合理处可异化为移动端自己的排版，由 agent 整体设计。
- 保留用户术语：「移动端适配」、「@docs/.html」（映射到 docs/index.html）。

---

## 范围与非目标

### In Scope

- docs/index.html 在窄屏（手机）宽度下的布局、字号、滚动与交互适配，覆盖页面全部模块，含第 7 模块的终端演示与目录树展示区。
- 对窄屏下不合理的桌面排版，整体设计异化的移动端排版逻辑（各模块统一设计，而非逐条修补）。

### Non-goals

- PC（桌面端）的排版与展示不做任何调整，本次全部改动仅限移动端生效范围。
- 不重做视觉风格、不改变文案与信息内容。
- 不为移动端另建独立页面或独立站点。
- 不涉及 docs 目录下的非 HTML 文件（图片、README 等）。

## 约束与保留术语

- 保留用户术语：「移动端适配」、「异化移动端的排版逻辑」；「@docs/.html」按仓库事实映射为 docs/index.html（docs 目录下唯一 HTML 文件）。
- 项目事实：该页为单文件页面，样式与脚本内联；已存在部分窄屏媒体查询（约 720/768/900px），本次为在其基础上的补齐与修复。

- **PD-1**：目标断点与具体阈值（在既有 720/768/900px 媒体查询基础上取舍或补充）。

- **PD-4**：验证手段与设备宽度集合（浏览器设备模拟的具体机型/宽度）。
