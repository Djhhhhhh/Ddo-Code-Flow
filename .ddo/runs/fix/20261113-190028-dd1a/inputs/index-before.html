01 · WHY

为什么需要它

直接让 AI 完成开发任务，过程不受约束：需求、方案、留档与接续都押在一次对话上。 Ddo-Code-Flow 不替代理写代码，而是把任务组织成可审核、可恢复的流程，用一个零依赖的 Node CLI 检查执行位置、输出契约与确认门。

// PAIN POINTS
  • ✗需求未对齐就动手实现
  • ✗方案没有审核就定稿
  • ✗过程与决策缺少留档
  • ✗会话中断后无法接续
  • ✗流程固定死板，无法按需组合

—— AI 单打独斗的默认工作方式，缺少流程约束。

// TRUST LOOP · 三方分工
执行内核组织
skill 的确定性流水线内核（零依赖 Node CLI）：提供当前指令、校验产物、检查位置与确认门、推进状态。不代替代理完成任务，不代替用户决议。
指令（exec）↓
代理执行
指宿主中的 AI coding agent（如 Claude Code、Codex）——skill 加载后由它完成实际工作：执行指令、校验产物、呈现选项并代跑合法命令。不手改 state，不自造选项，不替用户批准。
待审内容（gate present）↓
用户决议
显式调用、选择配置、审核关键交付并作出决议。不需要手动操作内部状态文件。

05 · CUSTOMIZE

自定义流程与配置

内置 26 个原子任务与 5 条预设只是起点。扩展不碰一行引擎代码——可自定义的只有三种东西，全是纯文件，新建即生效。

01原子任务atom-tasks/<名>/
一个目录就是一个任务：prompt.md 写指令，按 @phase:NN 分相位；config.json 声明相位、gate 选项与 output 产物契约。
02工作流workflows/<名>.json
stages 列出任务清单，dependOn 组成依赖图；when 按配置裁剪未启用的阶段并自动重接上下游。
03规则注入三层优先级
任务默认 ＜ 用户级（atom-tasks.json）＜ 运行级（--config 可重复 · 同键后者胜）；标量逐层覆盖，rules 数组逐层拼接。
不想手写？复制这段话发给你的 AI 
帮我给 ddo-code-flow 增加一个自定义原子任务「任务名」：

1. 参考 ~/.claude/skills/ddo-code-flow/atom-tasks/ 下现有任务的格式
2. 生成 prompt.md —— 任务指令，按相位分段（@phase:NN）
3. 生成 config.json —— 声明相位、gate 选项与 output 产物契约
4. 如需流水线：写 workflows/<名称>.json，stages + dependOn 组 DAG
5. 运行 list tasks 确认新任务已被识别
