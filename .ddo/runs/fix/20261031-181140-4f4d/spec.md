# 工具链设计合理性评估 Spec

> 本文档用于确认 agent 是否正确理解用户关于「评估本 skill 现有 CLI 子命令是否设计过度、过多、冗余，检查代码层面设计合理性，并依据结论实施精简」的需求。

---

## 对齐摘要

- 用户目标：判断本 skill 现有 CLI 子命令集是否设计过度、数量太多、存在冗余，并同步检查其代码实现的设计合理性。
- 评估动机：作为 agent 能力，工具不应过度设计，以防止 agent 执行过程中因检查/判断错误而选用错误的工具。
- 评估方法约束：结论须以 web search 调研到的外部实践与代码事实为证据，不以主观印象下结论。
- 期望交付：评估报告（结论 + 依据 + 建议）＋ 依据评估结论在本 run 内直接实施的 CLI 工具精简改动（BQ-2 已确认）。
- 当前状态：BQ-1、BQ-2 均已解决并写回，等待用户批准。

---

## 用户目标

- 评估现有 CLI 子命令集是否设计过度、是否太多、是否存在冗余（BQ-1：评估对象为 CLI 子命令集）。
- 通过 web search 调研该问题，作为评估参照。
- 设计动机：agent 能力不应配备过度设计的工具，防止执行中因检查错误而误用工具。
- 同步检查这些工具在代码层面上的设计是否合理。
- 依据评估结论在本 run 内直接实施精简（删除/合并/简化 CLI 工具），而非仅停留在建议（BQ-2）。

---

## 范围与非目标

### In Scope

- 清点 CLI 全部子命令，形成含职责与使用时机的完整命令清单。
- 通过 web search 调研 agent 工具设计的公开最佳实践（工具数量、职责划分、防误选等）。
- 基于调研参照逐命令评估：是否设计过度、是否太多、是否存在冗余（职责重叠/可合并/可删除）。
- 从代码层面检查 CLI 子命令实现的设计合理性，定位具体问题点。
- 产出评估报告：明确结论、逐项依据、改进建议。
- 依据评估结论实施 CLI 子命令的精简改动（删除/合并/简化），改动后流水线核心动作仍可用。

### Non-goals

- 原子任务集（任务定义、数量与结构）不作为本次评估与改动对象（BQ-1：仅 CLI 子命令）。
- 不评估、不改动与本 skill 无关的外部项目或工具库。
- 不虚构未检索到的外部实践作为依据。
- 不实施与评估结论无关的额外重构。
