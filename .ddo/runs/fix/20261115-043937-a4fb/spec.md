# @plugins 运行目录关联修复 Spec

> 本文档用于确认 agent 是否正确理解用户关于「@plugins 插件运行目录文件修复：插件与项目运行目录结构未关联，需排查再设计」的需求（rev 2，已按用户修订更新）。

---

## 对齐摘要

- 用户目标：基于对运行时状态文件体系（index.json、.state.json 等）的整体审查，重新设计插件与这些文件结构的整体关联并修复。
- 期望交付：状态文件体系整体盘点结论 + 经用户审查的整体设计方案 + 插件代码修复生效。
- 关键边界：插件保持只读；默认不重构引擎侧状态文件结构本身。
- 当前状态：BQ-1、BQ-2 已由用户修订（2026-11-15）解决，待用户批准本 spec。

---

## 用户目标

- 整体检查回顾运行时状态文件（`index.json`、`.state.json` 等）的结构信息并理解。
- 在此基础上整体设计插件与状态文件体系的关联，修复当前脱节。

---

## 范围与非目标

### In Scope

- 整体盘点状态文件体系：各文件的结构、语义、写入时机与插件当前利用情况，交付排查结论。
- 产出插件数据面的整体设计方案并送用户审查。
- 按审定设计修改 `plugin/` 内代码使其在插件界面生效。

### Non-goals

- 不给插件增加控制类能力（启动/推进/收口 run）。
- 不默认重构引擎侧状态文件结构本身（STATE-SPEC 语义为权威输入）；若设计结论表明必须引擎配合，先回到用户确认扩围。
- 不改动插件打包发布流程。

## 约束与保留术语

- 保留用户术语：`@plugins`（指本仓库 `plugin/` 目录的 VS Code 插件）、`运行目录`、`存活流水`。
- 项目事实约束：插件对索引与全部 state 只读（plugin/README.md Non-goal）。
- 项目事实约束：状态文件体系规范以 `tools/STATE-SPEC.md` 为权威——正常 run（含已收口）的完整 state 与产物保留在 `<projectRoot>/.ddo/runs/<type>/<runId>/`；临时 run 落 `~/.ddo/tmp/`（finish 后删除，仅留 history 归档）；`~/.ddo/index.json` 仅登记运行中 run（start 注册、finish 注销）；`~/.ddo/history/` 保存 `runs.jsonl` 历史事件与 zip 归档。

## 解释与假设

| 类型 | 内容 | 依据或原因 | 若错误的影响 |
|---|---|---|---|
| Interpretation | 「@plugins 插件」指本仓库 `plugin/` 目录中的 VS Code 存活流水查看插件。 | 仓库唯一插件目录；近期提交「feat(plugin): VS Code 存活流水查看插件 v0.2.17」。 | 若指其他外部插件，修复对象整体改变。 |
| Interpretation | 「没有关联起来」指：插件 run 发现仅读全局索引 `~/.ddo/index.json`（只含运行中 run），而状态文件体系的其余部分——项目内 `.ddo/runs/`（含已收口 run 的完整 state 与产物）、`~/.ddo/history/`（runs.jsonl 历史与 zip 归档）——对插件不可见或未利用。 | `plugin/src/runDiscovery.js` 事实 + STATE-SPEC §4.2 写入矩阵 + 实地盘点（本仓库 30+ 已收口 run 保留完整 state）。 | 若用户指其他脱节点，排查结论与新设计方向不同。 |
| Interpretation | 「整体设计这些文件的结构信息」指设计**插件对既有文件结构的整体利用方式**，而非重构状态文件体系本身。 | 用户语境「这个插件…修复」，修复对象是插件；引擎侧结构有 STATE-SPEC 权威规范。 | 若用户意图是重构文件体系本身，范围扩大到引擎侧，需用户确认。 |
