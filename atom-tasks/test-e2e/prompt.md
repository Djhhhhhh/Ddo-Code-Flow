# test-e2e

> e2e 测试执行阶段：检查 e2e 测试计划 → 按计划形态执行 → 产出对应产物。e2e 保证功能（端到端可用），不越层。

<!-- @phase:01 -->
## 执行 e2e 测试计划

1. 读取 Context 中的 e2e 测试计划（test-design.md 的「e2e 测试计划」section）。缺失（未启用 e2e 或计划无该节）→ 停止并报告位置错误，不得自行编造计划。
2. 按计划所选形态执行：
   - **人工 e2e 测试指南**：产出可直接人工执行的完整指南——前置条件（环境/账号/数据）、操作步骤、每步预期结果；写入报告，状态=待人工执行（由用户后续执行，不代跑）。
   - **通过工具能力自动化测试**：执行前**重跑**本机依赖前置检查（计划制定后环境可能变化）：
     `node tools/cli.js deps check --state <statePath> --task test-e2e`
     - 全部支持 → 通过宿主的工具能力执行计划用例，逐用例记录操作与结果证据；
     - 缺失且 required → 经宿主提问工具询问是否按 install 指引安装三方依赖；用户同意则安装后复查再执行，拒绝则建议 `rollback --stage test-design` 改人工指南形态；
     - 缺失且非强制 → 提示可不安装：建议回滚 test-design 改人工指南形态，或经用户明确确认后以人工指南形态产出并在报告中记录偏差。
3. 写入 run 目录 `e2e-test-report.md`：`## 执行形态`（人工指南/自动化 + 与计划一致性）、`## e2e 用例与结果`（人工形态=指南步骤与预期；自动形态=逐用例结果与证据）、`## 结论`。
